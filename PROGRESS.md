## v0.8.0: `allow` subcommand (2026-07-24, all tested)
- **What**: `npm-script-lens allow [--ci-check] [--input <json-file>]`. One-shot classifier that splits every package WITH install-time scripts into two buckets and emits `{ "allowScripts": { "<pkg@ver>": true }, "_review": ["<pkg@ver>", …] }` as JSON on stdout, plus `X packages auto-approved, Y need manual review.` on stderr.
  - Auto-approve (allowScripts → true): behavioral risk **SAFE or LOW** AND not known-malicious AND fetchable. Held for review (`_review`): **MEDIUM/HIGH**, known-malicious (OSV MAL-*), or ERROR (un-fetchable). Reuses `packageRisk` + the same `['SAFE','LOW']` auto-approve convention as `buildAllowScripts`/`review`/`sync`. Version-pinned keys, consistent with the rest of the tool.
  - `--input <file>`: classify a saved `audit --json` result (object with a `results` array, or a bare array) instead of re-scanning, no network. Throws a clear error on bad shape.
  - `--write`: closes the loop the `--ci-check` message advertises, merges the auto-approved (`true`) entries into package.json (preserving existing keys, reuses `projectPackageJson`/`writePackageJson`/`sortedBlock`). `_review` packages are deliberately LEFT OUT (writing them would decide for the user; absent = still pending for npm v12 + human). Nothing auto-approvable ⇒ file untouched.
