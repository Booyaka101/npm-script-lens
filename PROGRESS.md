## v0.8.0 — `allow` subcommand (2026-07-24, all tested)

## v0.8.0 — `allow` subcommand (2026-07-24, all tested)
- **What**: `npm-script-lens allow [--ci-check] [--input <json-file>]`. One-shot classifier that splits every package WITH install-time scripts into two buckets and emits `{ "allowScripts": { "<pkg@ver>": true }, "_review": ["<pkg@ver>", …] }` as JSON on stdout, plus `X packages auto-approved, Y need manual review.` on stderr.
  - Auto-approve (allowScripts → true): behavioral risk **SAFE or LOW** AND not known-malicious AND fetchable. Held for review (`_review`): **MEDIUM/HIGH**, known-malicious (OSV MAL-*), or ERROR (un-fetchable). Reuses `packageRisk` + the same `['SAFE','LOW']` auto-approve convention as `buildAllowScripts`/`review`/`sync`. Version-pinned keys, consistent with the rest of the tool.
  - `--input <file>`: classify a saved `audit --json` result (object with a `results` array, or a bare array) instead of re-scanning — no network. Throws a clear error on bad shape.
  - `--write`: closes the loop the `--ci-check` message advertises — merges the auto-approved (`true`) entries into package.json (preserving existing keys, reuses `projectPackageJson`/`writePackageJson`/`sortedBlock`). `_review` packages are deliberately LEFT OUT (writing them would decide for the user; absent = still pending for npm v12 + human). Nothing auto-approvable ⇒ file untouched.
  - `--ci-check`: **runs no scan**. Exits 1 iff (a) a `.github/workflows/*.y(a)ml` run-line matches `npm (install|i|ci)` (comment lines skipped), (b) package.json has no non-empty `allowScripts` block, AND (c) local npm major ≥ 12 (via `npmMajorVersion` — new export in src/review.js, honors `NPM_SCRIPT_LENS_NPM`). Message: `CI will break on npm v12: run lens allow to generate allowScripts block.` Any condition false → exit 0 with a one-line reason.
- **Reuse, no new src file**: all logic in src/cli.js (`classifyForAllow`, `allowAction`, `ciCheckAction`, `ciCheckResult`, `workflowsRunNpmInstall`). New exports: `npmMajorVersion` (src/review.js), `workflowFiles` (src/v12gaps.js), `ciCheckResult` (src/cli.js). No changes to analyzers/reporter.

Shares the exact detection with the CLI via `ciCheckResult` (no duplicated logic). On break: `::error::CI will break on npm v12: … run \`npx npm-script-lens allow --write\``, job-summary `## ❌`, exit 1. On pass: `## ✅` summary + reason, exit 0. Dispatch in action.js refactored to a `MODE` map (`v12-gaps`/`ci-check`/default `main`). action.yml re-verified as valid YAML (4 steps, 12 inputs).
- **Tests**: test/allow.test.js — 12 tests vs mock registry + stub npms: acceptance (3 LOW + 1 HIGH → 3 allowScripts / 1 _review + exact stderr summary), JSON shape (exactly `_review`+`allowScripts` keys, clean pkgs omitted), malicious-LOW held for review, `--input` reuse, `--write` (merges only auto-approved, preserves existing, leaves HIGH out) + `--write` no-op when nothing approvable, 4 `--ci-check` CLI paths (exit 1 on v12+install+no-allow; pass on existing allowScripts / npm<12 / no-install), and 2 Action e2e paths (`action.js ci-check` → exit 1 with `::error`+❌ summary on the break combo; exit 0 + ✅ summary when allowScripts present).
